## Phase E — Escalation engine (MVP-020–025)

| Item | Status | Notes |
|---|---|---|
| MVP-020 Policy configuration | ✅ | `EscalationPolicy` aggregate: 1–5 tiers (threshold, role, deadline, recommended action), follow-up owner. Revisions never edited; propose → approve by a different, supervisory user → effective from a stated time; reject, withdraw, restore-as-new-revision. Preview. Every decision is an event. **No default policy** |
| MVP-021 Automatic escalation | ✅ | `WaitingTimeMonitorService` every 15s per available tenant. One escalation per patient per tier, enforced by a unique index. Commands re-validated by handlers and audited as `System`. Steady-state evaluation of 150 waiting patients asserted < 1s. Failures logged and retried next tick |
| MVP-022 Manual follow-up | ✅ | `FollowUpException` aggregate, one per missed deadline (unique index), raised with the escalation's move to `ManualFollowUp` in one transaction. Closed by the owner or a supervisory role with an outcome and notes. Staff-raised escalations included |
| MVP-023 Board | ✅ API | `GET /escalations/board`: policy status, metrics, awaiting acknowledgement, active, follow-ups, history; live from the tenant DB, UTC timestamps. 150 escalations asserted < 500ms. **UI is Phase H** |
| MVP-024 Audit trail | ✅ | `GET /escalations/{id}/audit` JSON and CSV (formula-injection safe). Event and audit tables reject updates and deletes |
| MVP-025 Acknowledge / resolve / reassign | ✅ API | Acknowledge and resolve idempotent; reassign resets to awaiting acknowledgement against a new deadline. Every transition records actor role. **"UI workflow approved by clinical staff" is Phase H** |
| Verified live | ✅ | 2026-09-15 against Docker SQL Server: migration applied to both dev tenants; no-policy warning; self-approval refused (422); approval by Clinical Lead put revision 1 in force and the monitor immediately raised tiers 1–3 for a patient waiting since the previous day; ack twice, reassign, board and CSV audit export |

**Fixed along the way:** escalation events recorded every actor role as `"Staff"`; timestamps
read from the tenant database lacked a UTC marker, which a browser would show an hour out.

**Not done from MVP-020–025, and why**

| Criterion | State |
|---|---|
| Real-time push (<10s staleness) | Board is live on every request; push transport (SignalR) is the Phase H decision |
| Dashboard UI, mobile, WCAG AA, clinical UI approval | Phase H |
| Monitor dead-letter queue | Failed commands are logged at Error and retried every tick; no dead-letter store |
| "A/B tested with real data" | Needs a pilot site |
| Role checks (supervisory approval, closure authority) | Enforced in the domain, but roles are unauthenticated headers until Phase G |
| Patient data on the board | Unauthenticated read endpoint until Phase G; reads are not audited |

**Needs a decision**

- **Supervisory roles.** Clinical Lead, Operations Manager, Site Manager and Matron may approve
  policy and close any follow-up exception. That list is a clinical governance decision for the
  hazard log, as is the default follow-up owner (Operations Manager) for escalations raised
  without a policy.

## Phase G — API, authentication, integration (MVP-060–070)

| Item | Status | Notes |
|---|---|---|
| MVP-065 OIDC authentication | ✅ | JWT bearer from any OIDC provider (discovery or static keys), asymmetric algorithms only, configurable claim names, issuer-scoped actor ids. Tenant and acting role from verified claims only; tenant header must match; multi-role tokens select an acting role; System and Integration reserved. Refuses to start outside Development without it |
| Role-based authorisation | ✅ | Default role matrix → permissions. Every endpoint (fallback: authenticated) and every command declares one, enforced by test; commands checked in the pipeline so envelope and integration routes cannot bypass it. Site Administrator sees no patient data. Denials and patient-data reads audited |
| MVP-068 Error codes | ✅ | Stable `code` on every problem response, documented |
| MVP-062 Queries | ✅ | `GET /episodes/{id}`; `GET /boards/waiting` with location, state, wait and age filters and keyset cursors (verified on SQL Server). No acuity filter: acuity is not yet modelled |
| MVP-061 Command envelope | ✅ | `POST /commands`: command id, correlation id, expected version, idempotency key (reserve-then-run, bound to actor and request), same pipeline and permissions |
| MVP-064 Outbound webhooks | ✅ | Registration with secrets shown once and encrypted at rest; outbox fan-out in the same transaction; HMAC-signed with timestamp; backoff, dead letter, retry; allowlisted payload fields with no patient identifiers; SSRF checked at connect time |
| MVP-063 Inbound webhooks | ✅ | Per-source HMAC, ±5 minutes; message-id reservation for exactly-once effect; quarantine with review |
| MVP-066 HL7 v2 / FHIR adapter | ✅ scoped | ADT A01/A04/A03/A11 and FHIR R4 Encounter arrival/finished/cancelled → register/discharge/cancel as the Integration role; visit → episode links; HL7 ACKs. **Observations (ORU / FHIR Observation) not mapped: there is no observation model until Phase F** |
| MVP-060 / MVP-070 OpenAPI and versioning | ✅ | `/openapi/v1.json` in all environments, checked in and drift-tested; `docs/API-VERSIONING.md` covers URL versioning, compatibility rules, deprecation, event and schema versioning |
